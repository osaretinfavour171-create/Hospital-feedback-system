2. Behavioral Contract Specifications (BDD Gherkin Features)
These feature specifications define the executable behavioral rules for system implementation.
Feature 1: Nurse-Assisted Feedback Ingestion & Automated Escalation
`features/nurse_feedback_escalation.feature`
Feature: Nurse-Assisted Feedback Ingestion & Automatic Escalation
As a Ward Nurse using the SmartClinic EHR Modal
I want to submit patient rating and feedback
So that low ratings automatically alert department supervisors
Background:
Given the SQLite database is initialized with standard departments
Scenario: Submitting a positive rating (No Escalation)
When the nurse submits feedback with the following details:
visit_id | department_id | overall_rating | category_tags | raw_comment
VIS-2026-01 | OPD | 5 | STAFF_COURTESY | Great doctor attention
Then the API response status should be 200
And the feedback record should be stored in "patient_feedback"
And no alert should be generated in "hospital_alerts"
Scenario: Submitting a low rating (Triggers Automated Alert)
When the nurse submits feedback with the following details:
visit_id | department_id | overall_rating | category_tags | raw_comment
VIS-2026-02 | EMERGENCY | 1 | LONG_WAIT | Patient waited 4 hours.
Then the API response status should be 200
And "escalation_triggered" in the response should be true
And a record should be created in "hospital_alerts" with:
department_id | severity | status
EMERGENCY | HIGH | OPEN
---
Feature 2: WhatsApp Text Feedback & Medical Advice Guardrail
`features/whatsapp_guardrail.feature`
Feature: WhatsApp Text Processing & Medical Advice Guardrail
As a WhatsApp Patient Bot Router
I want to filter out medical diagnosis/dosage questions
So that clinical queries receive a refusal notice instead of being logged as feedback
Scenario: Processing operational feedback via WhatsApp text
Given the patient sends WhatsApp text "+2348011112222": "Pharmacy was out of antibiotics."
When the system processes the message via Groq LLM
Then the phone number should be hashed using SHA-256
And "guardrail_triggered" should be false
And the feedback entry should contain tag "DRUG_AVAILABILITY"
Scenario: Blocking medical advice queries
Given the patient sends WhatsApp text "+2348011112222": "What dosage of Amoxicillin should I give my child?"
When the system processes the message via Groq LLM
Then "guardrail_triggered" should be true
And the feedback record should NOT be written to "patient_feedback"
And the system response message should instruct the patient to contact a doctor immediately

3. Data Contract Validation Rules (Pydantic Verification)
The software components MUST enforce structural validation rules at system boundaries using Pydantic schemas.
specs/contracts.py
import re
from pydantic import BaseModel, Field, field_validator
from typing import List, Optional
class StrictNurseFeedbackContract(BaseModel):
visit_id: str = Field(..., min_length=3, max_length=50)
department_id: str
overall_rating: int = Field(..., ge=1, le=5)
category_tags: List[str] = Field(default_factory=list)
raw_comment: Optional[str] = Field(None, max_length=1000)
is_anonymous: bool = False
@field_validator("department_id")
@classmethod
def validate_department(cls, value: str) -> str:
allowed = {"OPD", "EMERGENCY", "PHARMACY", "BILLING", "WARDS"}
if value.upper() not in allowed:
raise ValueError(f"Invalid department. Must be one of {allowed}")
return value.upper()
class StrictWhatsAppContract(BaseModel):
phone_number: str
message_text: str = Field(..., min_length=3, max_length=2000)
@field_validator("phone_number")
@classmethod
def validate_e164_phone(cls, value: str) -> str:
pattern = r"^\+[1-9]\d{1,14}$"
if not re.match(pattern, value):
raise ValueError("Phone number must adhere to strict E.164 format (e.g., +2348012345678)")
return value
